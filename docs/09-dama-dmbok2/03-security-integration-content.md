# 03｜数据安全、数据集成与文件内容管理

> 对应原书第 7～9 章，PDF 第 282～421 页。

## 1. 第 7 章：数据安全

### 1.1 定义

数据安全通过策略、制度、流程和技术，为数据提供适当的身份认证、授权、访问控制和审计，确保合法用户能够正确使用数据，同时限制不适当的访问、修改、传播和销毁。

安全不只是“禁止访问”，还要在保护与业务可用之间取得平衡。

### 1.2 安全需求来源

- 法律法规与行业标准。
- 客户、员工、供应商等利益相关方的隐私和保密要求。
- 合同、保密协议和数据共享协议。
- 企业商业秘密和竞争优势保护。
- 业务连续性、审计和问责要求。
- 跨境、云服务和外包场景的特殊要求。

### 1.3 安全基本目标

| 目标 | 说明 |
|---|---|
| 机密性 | 只有获得授权的人或系统才能访问 |
| 完整性 | 数据不被未授权或错误修改 |
| 可用性 | 合法用户在需要时能够使用 |
| 可审计性 | 能够追踪谁在何时进行了什么操作 |
| 隐私保护 | 个人数据按照明确目的、范围和期限处理 |
| 合规性 | 满足法律、合同、制度和行业标准 |

### 1.4 数据安全实施流程

```text
识别数据资产和安全需求
→ 数据分类分级
→ 分析威胁、漏洞和业务影响
→ 制定安全制度与访问规则
→ 设计身份、权限、加密和审计控制
→ 实施并验证控制措施
→ 持续监控、响应事件和复盘改进
```

### 1.5 关键控制

- 最小权限和职责分离。
- 基于角色或属性的访问控制。
- 多因素认证和账户生命周期管理。
- 传输加密和静态加密。
- 数据脱敏、匿名化和令牌化。
- 数据导出、下载和批量查询限制。
- 访问与变更日志。
- 安全补丁、漏洞扫描和渗透测试。
- 备份、恢复和勒索攻击防护。
- 第三方和云服务安全评估。
- 数据保留、清理和安全销毁。

### 1.6 AI 应用特有安全风险

| 风险 | 控制方式 |
|---|---|
| Prompt 注入 | 输入隔离、工具权限限制、指令优先级和安全测试 |
| 越权检索 | 检索前过滤权限，不能只在回答后隐藏 |
| 数据泄露 | 脱敏、输出检测、租户隔离、禁止敏感数据进入外部模型 |
| 工具滥用 | 工具白名单、参数校验、审批、预算和停止条件 |
| 训练数据超范围使用 | 明确同意、用途、保留期限和退出机制 |
| 模型或供应商风险 | 数据处理协议、部署区域、日志策略和退出方案 |
| 不可追责 | 保存模型版本、Prompt、证据、工具调用和审批日志 |

### 1.7 安全指标

- 敏感数据识别和分级覆盖率。
- 权限复核完成率。
- 高风险账户和过度授权数量。
- 未授权访问、导出和泄露事件数量。
- 漏洞修复时长。
- 加密覆盖率。
- 审计日志完整率。
- 第三方风险整改完成率。

## 2. 第 8 章：数据集成和互操作

### 2.1 定义

数据集成描述数据在不同存储、应用和组织之间移动、转换和整合的过程；数据互操作描述多个系统依据共同协议交换并正确理解数据的能力。

集成不只是“接口打通”，还必须处理语义、格式、质量、权限、时效、错误恢复和血缘。

### 2.2 常见场景

- 系统迁移和数据转换。
- 数据仓库、数据集市和数据湖加载。
- ERP、CRM、售后、供应链等应用集成。
- 企业内部和外部组织之间的数据共享。
- 批处理、消息、事件流和实时同步。
- 外部数据采购与接收。
- 结构化、半结构化和非结构化数据整合。
- 数据虚拟化和联邦查询。

### 2.3 集成模式

| 模式 | 特点 | 适用场景 |
|---|---|---|
| 点对点 | 建设快，但接口数量增长后难维护 | 少量、临时集成 |
| 中心辐射 | 通过集成中心统一转换和路由 | 多系统企业集成 |
| 企业服务总线 | 通过标准消息和服务治理集成 | 传统企业服务架构 |
| API 集成 | 实时、服务化、边界清晰 | 业务系统和外部开放平台 |
| 消息 / 事件驱动 | 解耦生产者和消费者 | 实时状态、异步处理 |
| ETL | 提取后转换并加载 | 传统数据仓库 |
| ELT | 先加载再在目标平台转换 | 数据湖、云数仓和大数据 |
| 数据虚拟化 | 不复制或少复制，提供统一视图 | 多源查询和快速整合 |
| CDC | 捕获源系统数据变化 | 实时同步和增量处理 |

### 2.4 集成生命周期

```text
规划和需求分析
→ 数据源剖析
→ 定义业务语义、映射和质量规则
→ 设计架构、接口和错误处理
→ 开发、测试与性能验证
→ 部署、监控和对账
→ 管理变更、血缘和服务水平
```

### 2.5 接口契约应包含

- 业务目的和数据所有者。
- 输入、输出字段和业务定义。
- 数据类型、格式、枚举和必填规则。
- 更新频率、时区、时间戳和顺序要求。
- 身份认证、授权和敏感字段处理。
- 幂等性、重试、超时、限流和错误码。
- 对账方式和数据质量标准。
- 版本策略、兼容性和下线流程。
- 数据血缘、日志和审计要求。
- SLA、责任边界和支持联系人。

### 2.6 AI 项目中的数据集成

```text
用户请求
→ 身份与权限服务
→ 业务系统查询实时事实
→ 检索系统获取文档证据
→ 规则引擎判断风险和流程分支
→ LLM 理解、生成或规划
→ 工具 API 执行业务动作
→ 结果回写工单、日志和评测系统
```

常见错误是让 LLM 代替接口完成事实查询，或让 Agent 在没有契约、权限和幂等控制的情况下直接操作生产系统。

### 2.7 集成指标

- 接口成功率与错误率。
- 端到端时延。
- 数据延迟和新鲜度。
- 数据丢失、重复和对账差异数量。
- 失败重试与人工补数次数。
- 接口复用率和点对点接口数量。
- 变更导致的下游影响和故障数量。
- 血缘覆盖率与文档完整率。

## 3. 第 9 章：文件和内容管理

### 3.1 定义

文件和内容管理负责关系数据库之外的非结构化或半结构化信息，包括文档、邮件、网页、图片、音频、视频、聊天记录和扫描件等的采集、存储、访问、使用、发布、保留和处置。

对 AI 知识库而言，这一章比单纯的向量检索技术更基础，因为知识质量首先取决于内容生命周期是否受控。

### 3.2 业务驱动

- 法规和档案保留要求。
- 诉讼响应与电子取证。
- 业务连续性和知识保留。
- 提高检索、协作和复用效率。
- 防止重复、过时、冲突和失控传播。
- 将结构化数据与非结构化内容关联。

### 3.3 内容生命周期

```text
创建或接收
→ 分类与标记
→ 审核与批准
→ 发布与分发
→ 使用、协作和修订
→ 归档与保留
→ 合法冻结
→ 到期处置或永久保存
```

### 3.4 内容信息架构

内容要可管理和可检索，需要建立：

- 内容类型。
- 分类体系和受控词汇表。
- 标题、作者、来源、版本、语言等元数据。
- 适用产品、地区、客户、角色和时间范围。
- 审批状态、有效状态和保密级别。
- 内容之间的引用、替代、继承和冲突关系。
- 保留期限、合法冻结和处置规则。

### 3.5 AI 知识库内容治理

| 对象 | 必要字段或规则 |
|---|---|
| 原始文档 | 来源、文件哈希、版本、发布日期、责任人、权限 |
| 文档版本 | 生效时间、失效时间、替代版本、变更说明 |
| 文本块 | 所属章节、页码、父文档、语言、适用范围 |
| 知识条目 | 标准问题、结论、条件、步骤、风险等级、引用 |
| 图片和表格 | 标题、说明、与正文的关系、可访问文本 |
| 过期内容 | 停止检索、保留审计记录、指向新版本 |
| 冲突内容 | 标记冲突、确定权威来源、禁止模型自由选择 |

### 3.6 不应仅靠切片解决的问题

- 文档版本冲突。
- 表格跨页和图片信息丢失。
- 一个结论只适用于特定型号、固件或国家。
- 正文与附件之间存在引用关系。
- 用户权限只允许访问部分章节。
- 内容已失效但仍存在于向量索引。
- 同一主题在多份文档中表述不一致。

这些问题需要内容管理、元数据、主数据和治理共同解决。

### 3.7 内容质量指标

- 内容责任人覆盖率。
- 审核和批准完成率。
- 过期内容占比。
- 重复和冲突内容数量。
- 元数据完整率。
- 检索无结果率与错误引用率。
- 合法保留和处置任务完成率。
- 内容更新到索引生效的平均时长。
