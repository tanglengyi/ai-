# 09｜DAMA-DMBOK2 数据管理知识库

> 基于《DAMA 数据管理知识体系指南（原书第 2 版）》整理的结构化学习笔记。内容以概念重组、实践提炼和 AI 项目映射为主，不替代原书，也不复制原文。

## 1. 为什么把 DAMA 放进 AI 应用知识库

AI 应用的上限不仅取决于模型，还取决于数据是否可定义、可获取、可追溯、可授权、可评测和可持续维护。

DAMA-DMBOK2 可以帮助解决以下问题：

- 企业究竟拥有哪些数据，谁负责，谁有权使用？
- 客户、产品、设备、错误码等核心对象如何形成统一定义？
- 文档、数据库、实时接口和历史工单应如何组合？
- 数据质量、元数据、版本、血缘、权限和生命周期如何管理？
- AI 生成错误究竟源于模型、检索、源数据还是业务规则？
- 如何把一次性 Demo 变成长期可运营的数据与 AI 能力？

## 4. 建议学习顺序

### 路线 A：AI 产品经理 / 解决方案经理

```text
第1章 数据管理
→ 第3章 数据治理
→ 第5章 数据建模和设计
→ 第12章 元数据管理
→ 第13章 数据质量
→ 第7章 数据安全
→ 第10章 主数据和参考数据
→ 第15～17章 成熟度、组织与变革
```

重点不是数据库底层实现，而是能够回答：

- 业务对象和关键字段是什么？
- 数据责任和决策权属于谁？
- 正确答案、版本和质量标准如何定义？
- AI 使用了什么数据，是否有权使用，能否追溯？
- 上线后由谁维护，问题如何闭环？

### 路线 B：AI 应用架构 / 数据工程

```text
第4章 数据架构
→ 第5章 数据建模和设计
→ 第6章 数据存储和操作
→ 第8章 数据集成和互操作
→ 第9章 文件和内容管理
→ 第10～13章 主数据、数仓、元数据和质量
→ 第7章 数据安全
```

重点是把数据生命周期落实到接口、数据库、对象存储、向量库、数据管道、权限、监控和备份中。

### 路线 C：企业数据治理建设

```text
第1章 数据管理
→ 第3章 数据治理
→ 第15章 成熟度评估
→ 第16章 组织和角色
→ 第17章 组织变革
→ 根据问题补充第4～13章
```

## 5. DAMA 的三个核心图

### 5.1 DAMA 车轮图

数据治理位于中心，周围是数据架构、建模、存储、安全、集成、内容、主数据、数仓、元数据和质量。它表达的是：任何单一工具都不能独立解决企业数据问题。

### 5.2 环境因素六边形

每个知识领域都需要同时考虑：

- 目标和原则。
- 活动。
- 角色和职责。
- 交付成果。
- 方法。
- 工具。
- 组织和文化。
- 度量指标。

### 5.3 知识领域语境关系图

用类似 SIPOC 的方式描述：输入、供应者、活动、参与者、交付成果、消费者、工具、方法和度量指标。活动通常分为计划、控制、开发和运营四类。

## 6. 学习与落地原则

1. 不按名词背诵，以业务问题为入口。
2. 每个知识领域都要形成可交付物，而不是只形成观点。
3. 数据治理不等于开会，必须进入系统开发、运营和问题处理流程。
4. 数据质量不能只在出错后清洗，要从数据创建环节预防。
5. 元数据不是附属文档，而是实现检索、血缘、权限和解释能力的基础。
6. 不追求一次性覆盖所有数据，优先管理关键数据元素和高风险数据。
7. 成熟度提升应循序渐进，以可测量的业务结果验证价值。
