# 01｜数据管理基础、数据伦理与数据治理

> 对应原书第 1～3 章，PDF 第 31～133 页。

## 1. 第 1 章：数据管理

### 1.1 定义

数据管理是在数据和信息资产的整个生命周期中，制定并执行计划、制度、流程和实践，对数据进行交付、控制、保护和价值提升。

它不是单纯的数据库管理，也不是 IT 部门的独立职责，而是业务、技术、管理和治理共同承担的跨职能工作。

### 1.2 业务目标

| 目标 | 含义 |
|---|---|
| 满足信息需求 | 支撑客户、员工、管理者和合作伙伴完成任务与决策 |
| 保护数据资产 | 保证数据的完整性、可用性、隐私和保密性 |
| 提高数据质量 | 使数据适合具体业务用途，而不是只追求形式正确 |
| 降低风险 | 防止未经授权的访问、误用、泄露、丢失和错误决策 |
| 创造价值 | 支撑运营、分析、创新、产品和商业模式 |

### 1.3 数据管理十二项原则

1. 数据是具有独特属性的资产，使用时不会像实物资产一样被消耗。
2. 数据价值可以用经济语言表达，但价值与使用场景、时效和风险有关。
3. 管理数据首先是管理数据质量。
4. 管理数据必须依赖元数据。
5. 数据需要提前规划，而不是系统上线后再补救。
6. 数据需求应驱动技术决策，不能让技术反过来决定业务数据。
7. 数据管理是跨职能工作。
8. 数据管理需要企业级视角。
9. 数据管理需要从业务、技术、风险、伦理和用户等多个角度思考。
10. 数据必须按全生命周期管理，不同类型的数据有不同生命周期。
11. 数据既代表价值，也代表风险。
12. 有效的数据管理需要领导层承担责任。

### 1.4 数据生命周期

```text
规划
→ 设计和赋能
→ 创建或获取
→ 存储和维护
→ 使用与共享
→ 增强、聚合或生成新数据
→ 归档或处置
```

生命周期管理必须同时关注：

- 数据的创建来源。
- 数据的使用目的。
- 数据质量变化。
- 元数据和数据血缘。
- 权限与安全。
- 保留期限与销毁。

### 1.5 数据管理战略的核心交付物

| 交付物 | 主要内容 |
|---|---|
| 数据管理章程 | 愿景、业务案例、原则、目标、成功标准、风险和运营模式 |
| 范围声明 | 管理哪些数据、覆盖哪些组织和系统、由谁负责 |
| 实施路线图 | 项目、优先级、里程碑、角色、资源和时间计划 |
| 管理指标 | 质量、效率、风险、采用率、成本和价值指标 |

### 1.6 对 AI 项目的启示

AI 项目常见问题并不是模型不够强，而是：

- 不知道真实来源是什么。
- 不知道哪个版本有效。
- 文档、实时数据和业务规则混在一起。
- 没有责任人维护。
- 无法解释为什么生成这个答案。
- 没有质量基线和业务指标。

因此，RAG、Agent 和模型评测都应建立在数据生命周期和数据责任之上。

## 2. 第 2 章：数据处理伦理

### 2.1 定义

数据处理伦理关注如何以符合公平、尊重、责任、诚信、透明和信任的方式获取、存储、管理、使用和销毁数据。

合法只是最低要求。法律往往滞后于技术，组织仍需判断某种数据使用方式是否会伤害个人、群体或公共利益。

### 2.2 三类核心伦理问题

| 问题 | 需要考虑的内容 |
|---|---|
| 对人的影响 | 数据和算法会影响就业、信用、医疗、服务机会和社会评价 |
| 滥用可能 | 数据可能被误导性展示、越权使用、重新识别或用于原目的之外 |
| 经济价值与所有权 | 谁拥有数据，谁可以使用，是否获得知情同意，收益如何分配 |

### 2.3 数据伦理基本原则

1. **尊重他人**：尊重个人尊严、自主权和弱势群体权益。
2. **行善与不伤害**：最大化收益，最小化伤害和侵入性。
3. **公正**：避免因样本、规则、算法或历史数据造成不公平结果。
4. **尊重法律和公共利益**：不仅满足合规要求，还要考虑社会影响。
5. **透明与可问责**：说明数据来源、目的、处理方式、限制和责任人。

### 2.4 常见伦理风险

- 选择特定时间窗口或样本制造结论。
- 通过坐标轴、比例或图形形式误导用户。
- 使用定义不同的数据进行无效比较。
- 训练数据、抽样和分析方法中存在偏见。
- 不记录数据转换和修订历史。
- 匿名化不足，多个数据集结合后可重新识别个人。
- 未经授权将数据用于新用途。
- 让算法承担高风险决策，却没有解释、复核和申诉机制。

### 2.5 数据伦理文化建设

```text
评审当前做法
→ 识别伦理原则和风险
→ 制定制度与行为准则
→ 建立培训、沟通和升级渠道
→ 将伦理检查嵌入项目流程
→ 持续审计和监测
```

AI 项目需要额外检查：

- 训练数据和评测集是否存在群体偏差。
- 模型是否生成歧视性、误导性或高风险内容。
- 用户是否知道自己在与 AI 交互。
- 自动化决策是否允许人工复核和申诉。
- 日志、对话和反馈数据是否被超范围使用。

## 3. 第 3 章：数据治理

### 3.1 定义

数据治理是在管理数据资产过程中行使决策权和控制权，包括规划、监控和执行。

数据治理负责确定：

- 谁可以做什么决定。
- 哪些制度和标准必须遵循。
- 数据问题如何识别、升级和解决。
- 数据管理活动是否达到预期结果。

数据治理负责监督和决策，数据管理负责执行。两者不能混为一谈。

### 3.2 数据治理范围

| 范围 | 典型内容 |
|---|---|
| 战略 | 数据战略、治理目标、优先级和路线图 |
| 制度 | 数据访问、使用、质量、安全、保留和共享制度 |
| 标准 | 数据定义、模型、接口、质量和架构标准 |
| 监督 | 审计、记分卡、问题管理、整改和例外审批 |
| 合规 | 隐私、财务、行业和跨境数据要求 |
| 资产估值 | 数据价值、替换成本、风险成本和商业机会 |
| 数据项目 | 主数据、质量、元数据、数据平台和数据产品建设 |

### 3.3 治理原则

1. **可持续**：不是一次性项目，而是持续运营能力。
2. **嵌入式**：进入需求、设计、开发、发布、运营和采购流程。
3. **可度量**：以风险、质量、效率和业务结果证明价值。
4. **业务驱动**：治理服务于业务战略，而不是为了治理而治理。
5. **共担责任**：业务和技术共同负责。
6. **多层治理**：企业、业务域、项目和本地层级各有决策边界。
7. **基于框架**：明确委员会、数据所有者、数据管理专员和执行团队职责。
8. **原则导向**：用少量稳定原则指导大量制度和具体决策。

### 3.4 数据治理组织

常见角色包括：

| 角色 | 核心职责 |
|---|---|
| 高管发起人 / CDO | 提供方向、资源和跨部门推动力 |
| 数据治理委员会 | 批准战略、制度、优先级和重大问题处理方案 |
| 数据治理办公室 | 运营治理流程、维护标准、跟踪问题和指标 |
| 数据所有者 | 对某一数据域拥有最终业务决策权 |
| 业务数据管理专员 | 维护定义、规则、质量要求和日常问题 |
| 技术数据管理专员 | 负责模型、集成、数据库、元数据、质量工具等技术实现 |
| 数据消费者 | 使用数据并反馈质量、可用性和业务需求 |

### 3.5 运营模式

- **集中式**：企业级团队统一决策和执行。
- **分布式**：各业务单元独立治理，采用共同标准。
- **联邦式**：企业制定底线和共享标准，业务域保留局部决策权。

大型企业通常更适合联邦式治理：既保证客户、产品等核心定义一致，又允许不同业务域保留必要差异。

### 3.6 数据治理实施流程

```text
评估成熟度和变革能力
→ 识别业务驱动和高价值问题
→ 明确治理范围与组织触点
→ 制定章程、原则、制度和运营框架
→ 任命数据所有者与数据管理专员
→ 建立问题管理和升级流程
→ 将治理嵌入项目与运营
→ 建立记分卡和持续改进机制
```

### 3.7 问题管理闭环

```text
发现问题
→ 记录影响、范围和证据
→ 评估风险与优先级
→ 明确数据所有者和责任团队
→ 分析根因与备选方案
→ 决策、修复和验证
→ 更新制度、规则、元数据或流程
→ 关闭并复盘
```

### 3.8 治理度量指标

可从五类指标建立数据治理记分卡：

- **制度执行**：制度覆盖率、例外数量、审计通过率。
- **责任落实**：关键数据域所有者和管理专员任命率。
- **问题管理**：问题数量、平均解决时长、重复发生率。
- **数据质量**：关键数据元素达标率、质量趋势和业务影响。
- **业务价值**：减少的返工、风险、成本和决策时间。

### 3.9 AI 知识库治理示例

| 治理对象 | 需要决策的内容 |
|---|---|
| 知识源 | 哪些文档可以进入知识库，谁批准 |
| 版本 | 新旧手册冲突时哪个版本生效 |
| 权限 | 不同客户、国家、部门能看到什么 |
| 更新 | 谁维护，更新频率和失效规则是什么 |
| 质量 | 正确率、引用率、拒答率和升级率达到多少才可上线 |
| 风险 | 哪些问题必须拒答或转人工 |
| 日志 | 对话和反馈可以保存多久、是否可用于训练 |
