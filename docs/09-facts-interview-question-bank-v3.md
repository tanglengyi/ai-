## 0. 3.0 为什么升级

2.0 已经能够较好覆盖 RAG、Agent、微调、推理、评测、企业知识治理和 AI 项目落地，但它仍然偏向“把一个 AI 项目做出来”。

AI 产品经理的完整职责还包括：

```text
发现值得解决的问题
→ 判断市场和客户价值
→ 选择产品与技术方案
→ 组织研发交付
→ 建立数据和评测体系
→ 推动使用、增长和商业化
→ 管理成本、风险和产品组合
→ 复盘并规模化复制
```

因此，3.0 新增：

1. 通用产品经理基本功。
2. 数据分析、埋点、漏斗和 A/B 测试。
3. 商业模式、定价、毛利、销售、交付和续费。
4. MaaS、模型平台和开发者平台。
5. ToC AI 产品、增长和订阅。
6. 多模态、语音、图像和视频产品。
7. AI 硬件、机器人和端云协同。
8. 行为面试、跨团队推动和负责人能力。
9. 产品设计题、数据题、故障分析题和商业案例题。

### 0.1 内容来源与边界

**继承自原始资料与 2.0 的内容：**

- LLM、Transformer、RAG、微调、PEFT、Agent、推理、显存、分布式训练和评测。
- 文档解析、知识治理、权限、版本、拒答、人工升级和 LLMOps。
- 机器学习、NLP、Python 和算法岗补充题。

**3.0 新增内容：**

- 产品发现、用户研究、产品战略、经营分析、商业化、平台产品、增长、多模态和机器人。
- 这些新增内容用于补足 AI 产品经理岗位能力，不声称全部来自原始 PDF。

**使用原则：**

- 具体模型、框架、参数、价格和岗位要求会变化，面试前需要再次核验。
- 没有真实生产数据时，必须明确区分“设计目标、实验结果、灰度结果和生产结果”。
- 不以题量作为完成标准，以“能结合真实项目作答、能解释权衡、能用数据验证”为标准。

## 1. 3.0 三层能力模型

3.0 不再使用一套框架回答所有问题，而是区分项目、产品和经营三层。

## 1.1 项目层：FACTS-E

| 维度 | 含义 | 必须回答 |
|---|---|---|
| **F — Facts** | 业务事实 | 用户、场景、流程、Baseline、数据和风险 |
| **A — Approach** | 解决方案 | 比较规则、搜索、Prompt、RAG、微调、Workflow、Agent |
| **C — Core Technology** | 核心技术 | 数据、模型、检索、工具、权限和日志如何流转 |
| **T — Trade-offs** | 技术权衡 | 质量、成本、时延、风险、灵活性和维护成本 |
| **S — Success** | 落地结果 | 上线范围、使用情况、效率、质量、收入和成本 |
| **E — Evaluation** | 评测迭代 | 评测集、分层指标、错误归因、回归和监控 |

### 两分钟项目回答

```text
F：谁在什么流程里遇到什么问题？现状指标和风险是什么？
A：比较过哪些方案？为什么选择当前组合？
C：数据、检索、模型、规则、工具和权限如何流转？
T：方案最重要的特点、牺牲和边界是什么？
S：上线给谁，使用和业务结果如何？
E：怎样评测、定位失败、回归和持续改进？
```

## 1.2 产品层：Discover → Design → Deliver → Iterate

| 阶段 | 核心问题 |
|---|---|
| **Discover** | 问题是否真实、用户是谁、频率和损失多大、替代方案是什么 |
| **Design** | 产品定位、用户旅程、功能边界、交互、数据和技术方案 |
| **Deliver** | 优先级、排期、依赖、验收、灰度、上线和风险 |
| **Iterate** | 埋点、漏斗、反馈、实验、复盘和路线图 |

## 1.3 经营层：Market → Revenue → Cost → Retention → Scale

| 维度 | 核心问题 |
|---|---|
| **Market** | 市场、客户、竞争、采购和付费意愿 |
| **Revenue** | 定价、套餐、转化、合同、续费和扩容 |
| **Cost** | 模型、算力、数据、交付、标注、运维和销售成本 |
| **Retention** | 留存、活跃、采纳、客户成功和价值兑现 |
| **Scale** | 标准化、平台化、渠道化、跨行业和跨区域复制 |

## 2. 岗位覆盖地图

| 岗位方向 | 必修模块 | 深挖模块 |
|---|---|---|
| ToB AI 应用产品 | FACTS-E、RAG、Workflow、评测、交付 | 商业化、权限、行业数据治理 |
| AI Agent 产品 | Workflow、Tool Calling、Memory、评测 | Agent 平台、成本、轨迹分析和安全 |
| AI 解决方案产品 | 业务流程、方案选型、POC、验收 | 招投标、报价、交付和复制 |
| 模型评测产品 | Golden Dataset、Rubric、Judge、回归 | Benchmark、数据运营和评测平台 |
| AI 技术产品 | Transformer、微调、推理、LLMOps | 平台架构、SLA、容量和开发者体验 |
| MaaS/模型平台产品 | 模型接入、训练、部署、计费、权限 | GPU 资源、弹性、API 生态和多租户 |
| ToC AI 产品 | 产品体验、激活、留存、订阅、内容 | 长期记忆、社交传播和多模态 |
| 多模态 AI 产品 | 图像、视频、语音、文档智能 | 多模态评测、版权、安全和成本 |
| AI 硬件/机器人产品 | 传感器、状态机、任务、端云协同 | 仿真、OTA、安全、能耗和量产 |
| 搜索/推荐/广告 AI 产品 | 指标体系、召回排序、实验 | CTR、CVR、GMV、生成式推荐 |

### 2.1 对你当前求职方向的建议优先级

```text
P0：项目表达、业务流程、RAG、Agentic Workflow、评测、ROI
P1：数据分析、商业化、MaaS、推理成本、跨团队交付
P2：多模态、ToC 增长、推荐广告、算法公式和分布式训练
```

# 第一部分｜共同核心题库

## 3. F｜业务事实与问题

1. 这个项目由谁提出，触发事件是什么？
2. 使用者、决策者、采购者、付款者和维护者分别是谁？
3. 用户在流程中的哪个节点使用 AI？
4. AS-IS 流程每一步的角色、输入、输出、耗时和等待时间是什么？
5. 哪一步最耗时、最容易出错、最依赖经验？
6. Baseline 是多少，统计口径和时间窗口是什么？
7. 问题是高频低风险，还是低频高风险？
8. 不使用 AI，仅靠流程改造、规则或搜索能否解决？
9. 用户现有替代方案是什么，为什么仍然不满意？
10. 是否存在统一标准答案？部门口径冲突如何治理？
11. 核心业务对象、状态、事件和规则是什么？
12. 哪些字段缺失时必须追问？
13. 哪些事实来自文档、数据库、实时接口和人工经验？
14. 数据是否存在、可用、可授权、可持续更新？
15. 错误答案可能造成什么损失，由谁承担责任？
16. 哪些任务允许自动执行，哪些必须确认或转人工？
17. 第一阶段明确不做什么？
18. AI 是否嵌入原有工作流，还是增加了一套额外操作？
19. 谁负责知识、规则、Prompt、评测集和线上反馈？
20. 如果不做该项目，业务继续承担什么成本、收入损失或风险？

## 4. A｜解决方案与选型

1. 为什么不是传统搜索、FAQ 或规则系统？
2. Prompt、RAG、微调、Workflow、Agent 如何选择？
3. 为什么不把所有知识微调进模型？
4. 规则引擎和 LLM 如何分工？
5. 为什么优先受控 Workflow，而不是自由 Agent？
6. SQL、全文检索、向量库和知识图谱分别承担什么任务？
7. 信息不足时选择追问、拒答还是转人工？
8. 多型号、多地区、多版本如何路由？
9. 实时事实和静态文档冲突时，哪个来源优先？
10. 高风险问题如何人工兜底？
11. 模型、向量库、工具或第三方 API 失败时如何降级？
12. 自建、采购 SaaS、模型 API 和私有化部署如何选？
13. 基础模型如何比较质量、时延、成本、上下文和合规？
14. 多语言采用先翻译后检索，还是跨语言 Embedding？
15. 为什么需要结构化输出 Schema？
16. 为什么需要证据引用和引用校验？
17. Demo、MVP、灰度和生产化如何拆分？
18. 哪些“看起来智能”的能力实际没有业务价值？
19. 预算减少一半时保留哪项能力？
20. 如果模型供应商被替换，哪些资产仍然保留？

## 5. C｜核心技术实现

1. 画出一次请求的端到端链路。
2. 数据源如何接入、解析、清洗、去重、脱敏和授权？
3. PDF、Word、网页、表格、图片、日志和工单如何处理？
4. 为什么解析要保留标题、层级、页码、表格、图片说明和版本？
5. 文档元数据如何设计？
6. 固定、标题、语义、父子和句子窗口分块如何选？
7. Chunk Size 和 Overlap 如何通过实验确定？
8. 大表什么时候应使用 SQL 或结构化查询？
9. 为什么错误码和型号常需要 BM25，口语表达需要向量检索？
10. 混合检索如何进行加权或 RRF 融合？
11. Embedding 如何验证中文、多语言、术语和长文本能力？
12. Reranker 解决什么问题，不能解决什么问题？
13. 元数据过滤放在召回前还是召回后？
14. Query Rewrite 如何补全省略信息，又不虚构条件？
15. 复杂问题如何拆成多个子查询？
16. Top-K 和上下文 Token 预算如何确定？
17. 上下文如何去重、排序和处理冲突？
18. Prompt 如何约束仅基于证据回答？
19. 如何验证引用真正支持回答？
20. 如何实现正确拒答？
21. JSON Schema 如何校验和修复？
22. 工具调用如何处理参数、权限、幂等、重试和超时？
23. 短期对话、长期记忆和业务状态分别保存在哪里？
24. Trace 需要记录哪些节点和版本？
25. 如何支持知识增量更新、缓存失效和回滚？
26. 如何防止 Prompt Injection、越权和跨租户泄露？
27. 模型、Prompt、Embedding、索引和知识版本如何关联？
28. 如何设计模型路由和降级链路？
29. 如何监控请求量、P95 时延、成本、拒答和人工升级？
30. 如何区分模型错误、数据错误、流程错误和业务定义错误？

## 6. T｜技术特点与权衡

1. 方案最核心的技术特点是什么？
2. RAG 的优势和局限是什么？
3. 微调的优势和局限是什么？
4. Workflow 和 Agent 在可控性、灵活性、成本和风险上有什么差异？
5. 为什么更大的模型不一定更适合业务？
6. 如何权衡质量、时延、成本和风险？
7. Top-K 增大为什么可能降低答案质量？
8. Chunk 增大为什么可能提高完整性却降低召回精度？
9. Reranker 提升什么，又增加什么成本？
10. 长上下文塞全文与 RAG 的差异是什么？
11. 规则和 LLM 组合为什么更可靠？
12. 结构化事实和非结构化知识为什么应分开？
13. 多语言检索如何权衡翻译误差和跨语言 Embedding？
14. RAG 为什么仍然不能完全消除幻觉？
15. 如何避免将可能原因表达成确定结论？
16. Temperature、Top-P、Top-K 和重复惩罚如何影响结果？
17. INT8、INT4 量化如何影响显存、速度和质量？
18. 蒸馏、量化、剪枝和小模型路由如何选择？
19. 云 API 和私有化如何权衡安全、弹性和总成本？
20. 如何降低供应商锁定？
21. 何时技术复杂度已经超过业务收益？
22. 为什么离线指标提升，线上业务指标可能不变？
23. 为什么回答更流畅不等于任务完成得更好？
24. 你做过最重要的一次技术取舍是什么？
25. 哪些功能应明确不做？

## 7. S｜落地效果

1. 是否真实上线，上线到哪些用户和流程？
2. Baseline 和上线结果分别是什么？
3. 结果属于离线实验、灰度还是生产数据？
4. 使用率、活跃率、采纳率和任务完成率如何？
5. 处理时长、首次解决率、升级率和成本变化多少？
6. 效果提升来自模型、数据治理、流程改造还是规则统一？
7. 是否出现指标上升但用户体验下降？
8. 最常见失败类型及发生率是什么？
9. 出现严重错误时如何止损和回滚？
10. 减少了哪些人工工作，又增加了哪些维护工作？
11. 业务团队的职责发生了什么变化？
12. 是否真正减少研发和专家重复工作？
13. 模型、服务器、向量库、标注、评测和运维成本如何计算？
14. ROI 如何计算？
15. 哪些收益属于节省成本，哪些属于增加收入或降低风险？
16. 能否复制到其他部门、产品或地区？
17. 哪些目标未达到，为什么？
18. 重新做一次会优先改变什么？
19. 你的直接贡献是什么？
20. 如何证明成果不是团队整体结果的简单归功？

## 8. E｜评测与迭代

1. “准确率”具体指哪一层？
2. 检索、生成、系统和业务指标如何分层？
3. Golden Dataset 从哪里来，谁审核？
4. 如何覆盖真实业务分布和长尾？
5. 如何覆盖多条件、多轮、冲突、无答案、拒答、多语言和攻击样本？

7. 如何避免测试集泄漏和评测集过拟合？
8. Recall@K、Precision@K、MRR 和 NDCG 分别回答什么问题？
9. Faithfulness、Correctness、Relevance 和 Completeness 如何评分？
10. 正确拒答、有效追问、工具调用和人工升级如何评估？
11. Agent 如何评估任务成功率、轨迹效率和错误恢复？
12. 开放式回答 Rubric 如何设计？
13. 确定性规则、人工评测和 LLM-as-a-Judge 如何组合？

15. Go/No-Go 阈值如何定义？
16. 如何按数据、解析、检索、生成、工具、流程和业务定义归因？
17. 为什么实验最好只改变一个主要变量？
18. 实验需要记录哪些版本和参数？
19. 如何比较模型、Chunk、Embedding、Top-K 和 Reranker？
20. 如何联合评估质量、成本和时延？
21. A/B 测试、灰度和回滚如何设计？

23. 失败样本如何进入生产回归集？
24. 人工修改如何审核后再回写知识库？
25. 如何向客户解释系统无法保证 100% 正确？

# 第二部分｜通用产品经理基本功

## 9. 用户研究与需求发现

1. 你如何证明需求是真实问题，而不是用户提出的功能方案？
2. 访谈对象如何选择，多少样本才有价值？
3. 用户表达和真实行为冲突时相信哪个？
4. 如何区分高频低价值与低频高价值需求？
5. 如何识别用户、采购者、管理者和实际操作者的目标冲突？
6. 用户说“需要一个 AI 助手”，你会继续追问什么？
7. 如何用任务、触发条件、输入、决策和结果描述场景？
8. 如何判断是教育用户，还是改变产品？
9. 如何识别伪需求、老板需求和单一大客户需求？
10. 没有真实用户时，如何开展早期探索？

## 10. 产品定位与路线图

1. 一句话如何定义产品的目标用户、核心任务和差异化？
2. 竞品分析如何避免只做功能表格？
3. 直接竞品、替代方案和“不做任何事”如何比较？
4. 如何判断产品应做通用平台还是垂直场景？
5. 0→1 阶段最小闭环是什么？
6. MVP 应验证价值、可用性还是技术可行性？
7. 如何使用 RICE、MoSCoW、WSJF 或价值/成本矩阵？
8. 销售需求、技术债和战略需求如何排优先级？
9. 路线图发生变化时如何向管理层和客户解释？
10. 什么情况下应该下线功能？

## 11. 产品设计与体验

1. AI 产品为什么不能只设计“输入框+答案区”？
2. 用户如何知道 AI 能做什么、不能做什么？
3. 如何设计首次成功体验？
4. 结果可编辑、可重试、可追溯和可恢复如何设计？
5. 如何展示置信边界而不制造虚假确定性？
6. 流式输出、等待动画和中间步骤展示如何取舍？
7. AI 主动追问多少次会造成打扰？
8. 用户纠错如何设计，才能真正进入闭环？
9. 如何设计人工接管和上下文交接？
10. 如何在自动化程度和用户控制感之间平衡？

## 12. 项目推进与跨团队协作

1. 算法说效果不稳定，业务要求按期上线，如何处理？

# 第八部分｜3.0 新增高频答案卡

## 31. 卡 31｜如何判断一个问题是否需要 AI？

**30 秒回答**

> 我会先看任务是否包含非结构化理解、生成、复杂分类或跨来源信息整合，再判断传统规则、搜索和流程优化能否更低成本地解决。同时检查数据是否可得、输出是否允许概率性、错误风险是否可兜底，以及是否存在可测量的业务目标。只有 AI 的增量价值大于新增的不确定性和维护成本，才进入方案设计。

## 32. 卡 32｜如何回答“AI 产品的北极星指标是什么”？

> 北极星指标不能统一设为调用量。它应该反映用户获得的核心价值，例如成功完成的任务数、一次解决的工单数或被采纳的有效产出数。调用量、Token 和会话数属于过程指标；时延、成本、错误率和安全事件属于护栏指标。

## 33. 卡 33｜如何做 AI 产品定价？

> 先确定客户购买的价值单位，再决定收费单位。席位适合稳定的人均使用场景，调用或 Token 适合开发者平台，任务量适合结果明确的 Agent，项目费适合重交付和私有化。定价必须同时覆盖模型、算力、数据、交付、运维和客户成功成本，并通过套餐、额度、超额计费和预算预警控制毛利风险。

## 34. 卡 34｜如何计算 AI 产品 ROI？

```text
年度收益
= 节省人工时间价值
+ 增加收入
+ 避免损失和风险

年度总成本
= 模型与算力
+ 数据与标注
+ 研发与交付
+ 运维与客户成功
+ 组织变更成本
```

> ROI 不能只计算 Token 费用，也不能把所有节省时间都视为可直接裁减的人力。需要说明统计口径、兑现条件和时间周期。

## 35. 卡 35｜如何处理大客户定制？

> 先判断需求是否属于目标市场共性、是否能抽象为配置或平台能力、收入和战略价值是否覆盖长期维护成本。共性需求进入产品路线图，客户特有流程通过配置、插件或实施层解决，完全不可复用且破坏主架构的需求应单独报价或拒绝。

## 36. 卡 36｜如何回答“产品验收了但没人用”？

> 验收证明合同条款完成，不等于业务价值兑现。我会从用户权限、流程嵌入、培训、效果、时延、信任、管理机制和激励逐层排查，并观察激活率、有效使用率、任务成功率和用户分层。必要时重做流程，而不是继续增加功能。

## 37. 卡 37｜如何设计 MaaS 模型平台？

> MaaS 的主线不是“展示很多模型”，而是让开发者完成模型发现、试用、接入、评测、微调、部署、监控和结算。核心对象包括组织、项目、API Key、模型、数据集、实验、版本、部署实例、配额和账单；核心经营指标包括活跃开发者、上线应用、成功调用、收入、毛利和留存。

## 38. 卡 38｜ToC AI 产品如何提高留存？

> 先提高首次成功任务率，再让产品持续记住用户目标、沉淀资产并嵌入高频流程。留存不应依赖无限聊天，而应来自模板、历史结果、个人知识、工作流、协作或内容生态。需要同时控制结果质量、等待时间、成本、隐私和用户控制感。

## 39. 卡 39｜多模态产品如何评测？

> 多模态评测要分解为内容正确、指令遵循、跨模态一致、视觉或语音质量、时序一致、可编辑性、时延、成本和安全。自动指标适合格式和部分相似性检查，审美、自然度和业务可用性仍需人工或用户行为验证。

## 40. 卡 40｜AI 硬件产品与纯软件有什么不同？

> AI 硬件的最终指标是任务完成和安全，而不是单一模型准确率。产品经理需要同时管理传感器、算力、功耗、状态机、控制、环境、固件、App、云端、OTA 和售后。离线算法提升如果不能改善真实设备任务成功率，就不能视为产品成功。

## 44. 一票否决式失分

- 编造生产数据。
- 把设计目标当成已经实现的结果。
- 把所有问题归因于模型。
- 无法解释拒答、降级和人工兜底。
- 说不清准确率的分母和标注来源。
- 高风险任务没有权限和审计。
- 用模型名或框架名代替方案设计。
- 只讲功能，不讲用户、指标、成本和经营结果。
- 只讲收入，不计算交付、模型和维护成本。
